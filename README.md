# SDE Mentorship Exercises

Progressive Java exercises for building coding fundamentals, backend fluency, and interview readiness.

## Learning path

1. Word Frequency Counter — strings, maps, normalization, and tests
2. Two Sum — map-based lookup and complexity
3. Valid Parentheses — stacks and validation
4. Log File Analyzer — parsing, sorting, and aggregation
5. Contact Manager — classes, encapsulation, search, and clean design
6. Binary Search Toolkit — boundaries, iteration, and recursion
7. Linked List Utilities — nodes, pointers, reversal, and cycle detection
8. Tree Traversal — recursion, queues, and breadth-first search
9. Graph Navigator — adjacency lists, visited sets, and shortest paths
10. Task Tracker API — Spring Boot, REST, persistence, and integration testing

## Workflow

Each exercise has its own README under `exercises/`. Read the requirements before starting.

1. Create a branch from `main`, for example `exercise/01-word-frequency-counter`.
2. Implement the exercise in your own solution directory.
3. Add tests and a short solution README explaining your approach and complexity.
4. Run your tests locally.
5. Open a pull request into `main`.
6. Request review and respond to comments.
7. Do not merge your own pull request unless explicitly agreed.

The mentor will review correctness, code quality, tests, naming, structure, complexity, and your written explanation.

## Recommended solution layout

```
solutions/
  exercise-01-word-frequency-counter/
    README.md
    src/
    test/
```

You may use Maven or Gradle. Use Java 17 or later unless a different version is agreed.

## Definition of done

An exercise is ready for review when:

- The requirements are implemented.
- Tests cover normal cases and important edge cases.
- The code is readable and organized.
- The README explains the approach and complexity.
- The branch contains only the intended exercise changes.
- The pull request has a clear title and summary.
