# Contribution and Pull Request Guide

This repository is used for mentorship exercises. The goal is to practice professional development habits as well as solve problems.

## Before you code

- Read the exercise README completely.
- Create a branch from the latest `main`.
- Keep one exercise per branch and pull request.
- Do not copy solutions from the internet. You may use documentation, but be prepared to explain every line.

## Branch naming

Use:

`exercise/<number>-<short-name>`

Example:

`exercise/01-word-frequency-counter`

## Pull request checklist

Before opening a pull request:

- Confirm the code compiles.
- Run all tests.
- Add tests for normal cases and edge cases.
- Add or update the solution README.
- Explain your approach and time/space complexity.
- Review your own diff.
- Confirm that unrelated files are not included.

## Pull request format

Use a title such as:

`Exercise 01: Implement Word Frequency Counter`

Include:

- What you implemented
- How you tested it
- Any design decisions
- Questions or areas where you want feedback

The mentor will review the pull request and may request changes. Update the same branch and push additional commits until the exercise is approved.

## Review expectations

Feedback may cover correctness, naming, organization, object-oriented design, testing, complexity, readability, and maintainability. Approval means the exercise meets the current learning goal; it does not mean there is only one valid implementation.
